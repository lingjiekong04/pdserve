# 限制、缺口与后续工作

## 已知限制

1. 单机双GPU、一个P/D配对，TP=PP=1；无多机、多配对、NIXL或AgentCache实现。
2. 单文本completion、n=1，不支持批量、聊天/工具协议、自动重试或持久化作业。
3. 公平调度只在有等待队列时改变派发顺序；本次36个性能运行没有发生重排，不能证明它带来因果性能收益。
4. 活动参数32对应历史有效P/D slot29；双副本可64。对照是相同GPU的架构配置比较，不是总并发相同的算法消融。
5. 0.25/2.0 req/s是开放环输入速率，没有扫描最大容量。目录标签saturated不证明稳态饱和；低负载吞吐大体由输入决定。
6. 120请求/场景/配置，少数类别只有24请求。p99是有限样本描述，不提供总体尾延迟保证。
7. ITL只统计+1 token-count帧，覆盖率跨配置不同；不是所有token的无偏分布。首帧内多个token没有单独时刻。
8. Prefill完成到transfer_completed包含队列、worker和poll窗口，不是纯线速网络延迟。阶段可重叠，不相加。
9. P/D与混合副本轮询策略不同；repeat没有随机交错运行，存在时间、监测开销和重启的混杂。pd_fair长请求场景repeat波动明显。
10. 正式1440请求均成功，但还有1次失败尝试；0失败不能解释为整个开发过程无故障。失败证据私有保留。
11. 管理接口无鉴权，仅限回环实验。epoch恢复依赖操作者确认旧进程退出；未具备生产级授权、TLS和自动恢复。
12. 旧内核checked-pid不是无竞态的进程句柄；公开候选不带自动杀进程。Stage4堆栈管理器也没有本轮真实启动验收。

## 资源与复现缺口

- 模型本地文件哈希完整，上游revision未核实；权重未包含，没有未经验证的新下载哈希。
- 固定依赖及历史freeze已记录，旧wheel当前下载/安装未重新验证。
- 已验证合并补丁在私有stock字节上重建；新下载Git tag与pip发行包的字节等价仍需执行者用before hash检查。
- 新便携入口语法/CPU/干运行通过，未在新目录重新部署或运行真实GPU。
- GitHub仓库URL未提供；上传脚本由用户输入，不预设仓库存在或已推送。
- 没有模型任务效果、训练评测、真实业务验收或生产压测记录。
